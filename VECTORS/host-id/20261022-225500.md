## Position

Each host daemon's Host id is now its machine's own `hostname`. Jang chose this ("1 works").

- `scripts/deploy` reads `hostname` on the target and writes that as `ROGER_HOST_ID`. The `<host>` argument is only the ssh route now. The ssh config, `/etc/hosts` and the `agent-jail` alias were left untouched.
- Host ids before → after:
  - decent-spider: `decent-spider` → `decent-spider`.
  - the machine reached as `agent-jail`: `agent-jail` → `JangsJail`. Its Store `clock` was already `JangsJail`.
- `scripts/acceptance` no longer hard-codes `--host-id decent-spider` / `--host-id agent-jail`. `two_host_stack` reads each machine's `hostname`. `ROGER_REMOTE_HOST` still defaults to the alias `agent-jail`.
  - cross-host now also requires the remote Store's `clock` to equal the remote Host id.
  - claims now also requires the Board to place B on that Host id.
- `tests/process.rs`: `a_host_id_change_keeps_sessions_pending_mail_and_claims`.
- README `## Deploy` says where the Host id comes from.
- GLOSSARY `## Language`: the Stored at example now reads `"clock":"JangsJail"`.
- The frozen `## kernel` Host id example (`agent-jail`) and KERNEL proof 1 are unchanged. `agent-jail` stays valid there as the name the machine is reached by.
- No core code changed. The deployed binary sha256 is still e93779fe…; only the env and the record changed.

## Tried

- How the core handles a Host id change, from reading `src/coordinator.rs`:
  - The Host id is only a routing attribute of a session (`host_of`).
  - Mail is keyed by its recipient Address and claims by their owner Address.
  - A Register through a different Host id commits a new `session` event and pushes that session's pending Mail.
  - A session that never re-registers is disconnected and expires after the grace period, like any other.
  - Pinned by the new process test: inbox-held Mail and coordinator-held Mail are each delivered once, there is one receipt each, the claim is still held and renewable, and the Board shows `host=host-b-renamed`.
  - Bite: making Register skip the `session` event for a known Address fails that test on the Board line.
- Bite on acceptance: running the remote daemon with `--host-id $REMOTE_HOST` fails claims with `board must place … on Host id JangsJail`. cross-host's clock check pins hostname and Store `clock` agreeing; it does not depend on the daemon flag.
- `scripts/check-all` rc=0: 15 unit and 31 process tests, harness-free, frozen, no-poll and both shims. Log: `/tmp/rw-hostid-checkall.log`.
- Acceptance cross-host, broadcast and claims, each rc=0. Logs: `/tmp/rw-hostid-accept/`.
- Live state before deploy: both Boards were empty (0 sessions, 0 claims), and no directed Mail was pending.
- Backups: `~/.local/share/host-id-backup-20261022-225257/` on both hosts.
- `scripts/deploy decent-spider main` reported PASS (`host id decent-spider`). `scripts/deploy agent-jail main` reported PASS (`host id JangsJail`).
- Live Tracers:
  - `roger board` showed `host=decent-spider` for the local Tracer and `host=JangsJail` for the remote one.
  - `hostid-l2r-1`: RECEIPT r-1, `latency_ms=203`, remote Store `"clock":"JangsJail"`.
  - `hostid-r2l-1`: RECEIPT r-1, `latency_ms=49`, local Store `"clock":"decent-spider"`.
