## Judgement on finding 9 (Board claims in key order)

Not a violation. Invariant 3 forbids code that branches on, ranks, or names the integers. `BTreeMap` orders by the key's bytes as one opaque string; it never parses an integer out of `[[153:Meteor Shower:7]]`, and a key `[[9:a:0]]` sorts after `[[153:...]]` because '9' > '1', which shows no numeric reading happens. The order is a property of the storage, not an interpretation. Left as is; the doc says "in key order", which is accurate.
